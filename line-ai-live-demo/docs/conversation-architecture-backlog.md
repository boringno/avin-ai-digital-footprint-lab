# 對話架構瘦身待辦

目標：讓客服先理解客人當下真正的問題，再由規則保護少數不可出錯的事實；不再靠持續新增關鍵字與固定話術修補單一案例。

## P0：本輪完成並供真機驗證

- [x] 建立單一 `activeFocus`，記錄目前療程、困擾、目標、已回答主題與下一個待確認問題。
- [x] 保留最近 6 個來回片段，遮蔽電話、Email 與網址後提供給回覆模型。
- [x] 價格只依本輪明確療程或目前諮詢焦點回答；舊預約草稿不得蓋過新療程。
- [x] ONDA 連續短答要承接前文並往下推進，不再重貼介紹或重複三選一選單。
- [x] 把「自然語氣與功能性 emoji」交給回覆層；規則層只提供事實底稿。
- [x] 以多輪、切換療程、修正答案、舊預約＋新價格等情境做回歸測試。

## P1：診所真機回饋後

- [ ] 將「意圖／焦點／下一步」規劃器先以 shadow mode 記錄，不直接改客人回覆。
- [ ] 建立診所驗收對話集：首次介紹、連續短答、跨療程、價格、預約、FAQ 缺漏。
- [ ] 量測重複率、無效反問率、預約推進率與人工接手率，再決定切換範圍。

## P2：逐步取代大型 router

- [ ] 讓 planner 輸出結構化 `activeFocus` 與單一 `nextAction`。
- [ ] 規則層縮到：院內供應、核准價格、活動日期隱藏、緊急事件、整形外科、預約欄位。
- [ ] FAQ、療程 pack 與官方資料只作知識素材，由回覆層依對話自然組織。

## P3：刪除舊包袱

- [ ] 依 eval 證明後刪除重複的固定句、特例關鍵字與無效二次路由。
- [ ] 移除與新 planner 重疊的 consultation state，只保留一份狀態來源。
- [ ] 將舊 `reply-tone` 後處理改成純格式／署名處理，避免疊加話術。

## 診所驗收標準

1. 客人已回答的療程、部位、困擾，不再重問。
2. 同一句短答重複一次時，客服要往下提供新資訊，不得原句重播。
3. 新療程／新困擾會覆蓋舊焦點，但不刪除尚未送出的預約資料。
4. 問價格只回診所核准資料，且不得顯示活動日期。
5. 「想了解」不誤進預約；只有明確預約才收姓名、電話、館別與時段。
6. 回覆自然、手機易讀，emoji 用於提示重點，不用制式選單填滿每一輪。
