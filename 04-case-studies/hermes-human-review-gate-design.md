# Case Study：Hermes Agent + Human Review Gate 設計

**日期：** 2026-05
**狀態：** 完成 Phase 1

## 問題
想建立一條 Agent 自動化支線，但不想讓 Agent 直接修改主系統，需要設計一個「Agent 提候選、人審核、再決定是否回收」的架構。

這個問題的核心不是能不能自動化，而是能不能在不失去控制權的前提下，把 Agent 納入真實工作流。對 AVIN 來說，主系統包含 Notion、GitHub 與對外公開資產，一旦讓 Agent 直接寫入，風險就會從效率問題升級成治理問題。

## 設計
- Mac mini 作為 Agent Home Base，Windows 筆電作為人工控制台
- Agent 只產生候選輸出，不直接寫入主 Notion 或 push 到 GitHub
- 所有輸出都必須經過 Human Review Gate 才能進入主系統
- 設定明確的 Stop Conditions（無法確認路徑、影響公開資產、含敏感資料）

這個設計把「產生內容」與「批准進主系統」拆成兩個責任層。Agent 專注於提案、整理、歸納與輸出候選；人類保留最終判斷權，負責檢查內容是否正確、是否適合公開、是否符合現有系統邊界。

## 工具
- Mac mini（Agent 執行環境）
- Hermes（Agent 命名）
- Notion（主系統 / 審核介面）
- GitHub（公開證據層）

## 人工介入點
- 每次 Agent 產生候選輸出後，AVIN 手動審核
- 決定：採用 / 修改後採用 / 丟棄
- 只有通過審核的內容才進入 Notion 或 GitHub

人工介入點不是補洞，而是這套架構的正式節點。它讓 Agent 的價值集中在「加速候選產出」，而不是假設 Agent 已經可靠到可以直接操作主系統。

## Stop Conditions
- 無法確認目標路徑或目標系統
- 內容可能影響公開資產，但尚未完成人工確認
- 涉及敏感資料、憑證、權限或不可逆操作
- Agent 無法判斷輸出是否符合既有規則或格式

一旦觸發任一條件，流程就必須停止在候選層，不進入正式回收。

## 產出
- Phase 1 smoke test 完成
- Human Review Gate 架構確認可運作
- 建立 Stop Conditions 清單

這個階段的成果不是追求全自動，而是先確認最小可行治理結構成立。只要候選輸出、人工審核與回收節點都能穩定分離，後續就能在不破壞主系統的前提下擴大 Agent 工作面。

## 可複用？
Yes — 這套「Agent 提候選 + 人審核」的架構可套用到任何需要 AI 自動化但不想失去控制的場景。

特別適合以下情境：
- 對外公開內容發布前的審核流程
- 內部知識庫或 SOP 草稿生成
- 多工具串接但不適合直接自動寫回的工作流
- 需要保留明確責任邊界的個人或小團隊系統
